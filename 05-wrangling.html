5  Transforming and summarizing data with dplyr

5.1 Learning outcomes

Use selection, filtering, transformation, recoding, sorting, grouping, joins, stacking, and reshaping to answer agricultural questions while preserving observational units; build field-book tables, growth-rate tables, and descriptive summary tables for reports.

5.2 A grammar of data manipulation

select() chooses columns, filter() chooses rows, mutate() creates or changes columns, arrange() orders rows, and summarise() reduces observations to summaries. group_by() controls the groups within which later operations occur. These verbs express a sequence of data operations; the pipe passes each result to the next step.

library(dplyr)

Attaching package: 'dplyr'
The following objects are masked from 'package:stats':

    filter, lag
The following objects are masked from 'package:base':

    intersect, setdiff, setequal, union
crop <- read.csv("data/crop_trial.csv")
crop |>
  filter(treatment != "Control", yield_t_ha > 4) |>
  select(plot_id, treatment, yield_t_ha) |>
  arrange(desc(yield_t_ha)) |>
  head()
  plot_id treatment yield_t_ha
1    P045   Mineral       5.16
2    P036   Mineral       4.86
3    P047   Mineral       4.84
4    P046   Mineral       4.72
5    P023   Mineral       4.55
6    P041   Compost       4.52

filter() keeps rows where its condition is TRUE; an NA condition is not retained. State explicitly whether missing records should be included. mutate() generally preserves the number of rows; summarise() changes the observational level.

crop <- crop |>
  mutate(yield_kg_ha = yield_t_ha * 1000,
         nitrogen_band = if_else(nitrogen_kg_ha >= 80, "Higher", "Lower"))
treatment_summary <- crop |>
  group_by(treatment) |>
  summarise(n_plots = n(), n_yield = sum(!is.na(yield_t_ha)),
            mean_yield = mean(yield_t_ha, na.rm = TRUE),
            sd_yield = sd(yield_t_ha, na.rm = TRUE), .groups = "drop")
treatment_summary
# A tibble: 3 × 5
  treatment n_plots n_yield mean_yield sd_yield
  <chr>       <int>   <int>      <dbl>    <dbl>
1 Compost        20      20       3.84    0.406
2 Control        20      20       3.12    0.488
3 Mineral        20      20       4.36    0.340

The treatment table has one row per treatment, whereas the original table has one row per plot. It cannot support analyses that require individual plot variation. .groups = "drop" prevents accidental retention of grouping in later operations. If every yield in a group is missing, mean(..., na.rm = TRUE) returns NaN; handle that group as having no usable estimate.

5.4 Joining tables safely

A join links records by keys. Here the soil table has one record per plot. Verify key uniqueness and unmatched records before accepting a join. Many-to-many joins can silently multiply observations and change subsequent averages.

stopifnot(!anyDuplicated(soil$plot_id))
anti_join(crop, soil, by = "plot_id")
 [1] plot_id        block          treatment      variety        replicate     
 [6] nitrogen_kg_ha rainfall_mm    yield_t_ha     yield_kg_ha    nitrogen_band 
<0 rows> (or 0-length row.names)
linked <- left_join(crop, soil, by = "plot_id")
stopifnot(nrow(linked) == nrow(crop))
head(linked[, c("plot_id", "yield_t_ha", "ph")])
  plot_id yield_t_ha   ph
1    P001       2.42 5.48
2    P002       2.82 6.02
3    P003       2.40 6.07
4    P004       2.86 6.79
5    P005       3.52 6.44
6    P006       3.14 5.69

left_join() retains all rows of the first table, adding NA when there is no match. inner_join() retains only matched rows. A row count check is necessary but not sufficient: inspect identifier meaning and measurement timing too.

5.5 Wide and long forms

Wide tables put several measurements in separate columns; long tables use a variable column and a value column. Long form is convenient for grouped graphics.

soil_long <- soil |>
  select(plot_id, available_n_mg_kg, available_p_mg_kg) |>
  tidyr::pivot_longer(-plot_id, names_to = "nutrient", values_to = "mg_kg")
head(soil_long)
# A tibble: 6 × 3
  plot_id nutrient          mg_kg
  <chr>   <chr>             <dbl>
1 P001    available_n_mg_kg  30.2
2 P001    available_p_mg_kg  21  
3 P002    available_n_mg_kg  33.6
4 P002    available_p_mg_kg  21.8
5 P003    available_n_mg_kg  32.9
6 P003    available_p_mg_kg  16

Do not average nitrogen and phosphorus merely because both are expressed in mg/kg. They are distinct quantities. Reshaping changes representation, not scientific meaning.

5.6 Understanding what happens inside a grouped operation

When we write group_by(treatment), R does not immediately replace the observations with treatment means. It adds grouping information to the table. The next operation then acts within each group. This distinction explains why mutate() and summarise() can give very different tables after the same grouping command.

within_treatment <- crop |>
  group_by(treatment) |>
  mutate(treatment_mean = mean(yield_t_ha),
         deviation_from_treatment = yield_t_ha - treatment_mean) |>
  ungroup()
head(within_treatment[, c("plot_id", "treatment", "yield_t_ha",
                          "treatment_mean", "deviation_from_treatment")])
# A tibble: 6 × 5
  plot_id treatment yield_t_ha treatment_mean deviation_from_treatment
  <chr>   <chr>          <dbl>          <dbl>                    <dbl>
1 P001    Control         2.42           3.12                   -0.704
2 P002    Control         2.82           3.12                   -0.304
3 P003    Control         2.4            3.12                   -0.724
4 P004    Control         2.86           3.12                   -0.264
5 P005    Compost         3.52           3.84                   -0.316
6 P006    Compost         3.14           3.84                   -0.696
nrow(within_treatment)
[1] 60
nrow(treatment_summary)
[1] 3

The first result still has 60 plot rows. Every plot carries its treatment’s mean and its own deviation from that mean. The summary table has only three treatment rows. If the purpose is to investigate within-treatment variation, the first table is useful. If the purpose is a compact reporting table, the second is useful. Neither representation should be confused with additional independent replication.

The word n() counts rows in a group. It does not automatically count nonmissing yields. Thus a group can have ten rows but only eight observed yields. The quantities n(), sum(!is.na(yield_t_ha)), and mean(yield_t_ha, na.rm = TRUE) must be interpreted together.

5.7 Weighted means and unequal harvested areas

Let us suppose two farms harvest 1 ha and 9 ha, with yields of 2 and 6 t/ha respectively. Their arithmetic mean yield is 4 t/ha. However, total production is 56 tonnes on 10 ha, so the area-weighted yield is 5.6 t/ha. Both calculations are arithmetically correct; they answer different questions.

farms <- data.frame(farm = c("Small", "Large"), area_ha = c(1, 9),
                    yield_t_ha = c(2, 6))
farms <- farms |>
  mutate(production_t = area_ha * yield_t_ha)
c(mean_farm_yield = mean(farms$yield_t_ha),
  yield_from_totals = sum(farms$production_t) / sum(farms$area_ha),
  weighted_mean = weighted.mean(farms$yield_t_ha, farms$area_ha))
  mean_farm_yield yield_from_totals     weighted_mean 
              4.0               5.6               5.6

The arithmetic mean describes the average yield of these two farm records when each farm receives equal weight. The weighted mean describes production per hectare across their combined harvested area. Before reporting a district, season, or treatment summary, ask what should receive equal weight. A column of weights must have a scientific interpretation; arbitrary weights cannot improve an analysis merely by changing the result.

5.8 Joining is not matching by row position

If soil rows have been sorted by pH while crop rows remain sorted by plot number, using cbind() to combine them would attach soil measurements to the wrong plots. A join uses an identifier instead. We can demonstrate this by deliberately changing the soil row order.

soil_reordered <- soil[order(soil$ph), ]
joined_by_id <- left_join(crop, soil_reordered, by = "plot_id")
stopifnot(identical(joined_by_id$plot_id, crop$plot_id))
all.equal(joined_by_id$ph, linked$ph)
[1] TRUE

The pH values remain correctly aligned because the join uses plot_id. A correct key is therefore more valuable than a visually tidy row order. For data collected at several depths or dates, plot_id alone may not be unique; the key might need plot_id, depth_cm, and sampling_date. A one-to-many relationship can be legitimate, but the resulting observational unit must be stated.

5.10 Recoding values with case_when()

if_else() handles two outcomes. For several, use case_when(), which checks conditions in order and uses the first one that is TRUE.

crop <- crop |>
  mutate(n_class = case_when(
    nitrogen_kg_ha < 40 ~ "Low",
    nitrogen_kg_ha < 80 ~ "Medium",
    nitrogen_kg_ha >= 80 ~ "High"
  ))
crop |>
  count(n_class)
  n_class  n
1    High 20
2     Low 20
3  Medium 20

Because the conditions are checked in order, a plot with 30 kg N/ha matches < 40 and is labelled “Low” even though it also satisfies < 80. Write conditions from the most restrictive to the least. A value that matches no condition, including a missing nitrogen value, becomes NA, which is usually what you want: an unknown dose should not be given a class.

5.11 Applying one operation to many columns with across()

Soil data often have many nutrient columns that need the same summary. across() applies one or more functions to a set of columns without repeating code.

soil |>
  group_by(soil_class) |>
  summarise(n = n(),
            across(c(ph, available_n_mg_kg, available_p_mg_kg),
                   list(mean = mean, sd = sd)),
            .groups = "drop") |>
  mutate(across(where(is.numeric), \(x) round(x, 2)))
# A tibble: 3 × 8
  soil_class     n ph_mean ph_sd available_n_mg_kg_mean available_n_mg_kg_sd
  <chr>      <dbl>   <dbl> <dbl>                  <dbl>                <dbl>
1 Clay loam     20    6.37  0.65                   39.6                 6.46
2 Loam          20    6.21  0.56                   37.5                 7.27
3 Sandy loam    20    6.19  0.65                   35.6                 8.86
# ℹ 2 more variables: available_p_mg_kg_mean <dbl>, available_p_mg_kg_sd <dbl>

The new columns are named by joining the column and function names, such as ph_mean and ph_sd. where(is.numeric) selects every numeric column, and \(x) round(x, 2) is a short way of writing function(x) round(x, 2). Rounding is done last, for display only; never round values before calculating with them.

5.12 Reshaping a field book with pivot_wider()

Plot-level data are stored long, one row per plot. For checking a design or for hand calculation, the traditional layout is wide: one row per block and one column per treatment. pivot_wider() makes that table, and pivot_longer() reverses it.

If a block lacked a treatment, the wide table would show NA in that cell, which makes a missing plot easy to see. If a block had two plots of the same treatment, pivot_wider() would warn that values are not uniquely identified. That warning is a design check: it means the key (block and treatment) does not identify one plot.

5.13 Splitting and joining codes

Field books often combine information in one code, such as T2-R3 for treatment 2 in replicate 3. separate_wider_delim() splits such a column, and unite() joins columns back into a code.

coded <- data.frame(plot_code = c("T1-R1", "T1-R2", "T2-R1", "T2-R2"),
                    yield_t_ha = c(3.2, 3.5, 4.1, 3.9))
split_codes <- coded |>
  tidyr::separate_wider_delim(plot_code, delim = "-",
                              names = c("treatment", "replicate"))
split_codes
# A tibble: 4 × 3
  treatment replicate yield_t_ha
  <chr>     <chr>          <dbl>
1 T1        R1               3.2
2 T1        R2               3.5
3 T2        R1               4.1
4 T2        R2               3.9
split_codes |>
  tidyr::unite("plot_code", treatment, replicate, sep = "-")
# A tibble: 4 × 2
  plot_code yield_t_ha
  <chr>          <dbl>
1 T1-R1            3.2
2 T1-R2            3.5
3 T2-R1            4.1
4 T2-R2            3.9

Splitting a code is safe only if every code follows the same pattern. separate_wider_delim() stops with an error if a code has too few or too many pieces, which is a useful check on data entry.

5.14 Stacking seasons with bind_rows()

Data from different seasons, sites, or years usually arrive in separate files with the same columns. bind_rows() stacks them, and .id records where each row came from.

kharif <- data.frame(plot_id = c("P01", "P02", "P03"),
                     yield_t_ha = c(4.1, 4.4, 3.9))
rabi <- data.frame(plot_id = c("P01", "P02", "P03"),
                   yield_t_ha = c(3.2, 3.6, 3.1))
seasons <- bind_rows(kharif = kharif, rabi = rabi, .id = "season")
seasons
  season plot_id yield_t_ha
1 kharif     P01        4.1
2 kharif     P02        4.4
3 kharif     P03        3.9
4   rabi     P01        3.2
5   rabi     P02        3.6
6   rabi     P03        3.1
seasons |>
  group_by(season) |>
  summarise(mean_yield = mean(yield_t_ha), .groups = "drop")
# A tibble: 2 × 2
  season mean_yield
  <chr>       <dbl>
1 kharif       4.13
2 rabi         3.3

Without the season column, the stacked table would contain two rows for each plot with nothing to tell them apart. Always keep the identifier of the source when combining tables. Check also that columns have the same names and units in every file before stacking; bind_rows() matches columns by name and fills missing ones with NA.

5.15 Changes over time with lag()

Growth analysis compares each observation with the previous one. lag() shifts a column down by one row, so the difference between a value and its lag is the change since the last sampling date.

growth <- read.csv("data/growth.csv")
growth |>
  group_by(day) |>
  summarise(n = n(), mean_biomass = mean(biomass_g_m2), .groups = "drop") |>
  arrange(day) |>
  mutate(gain_g_m2 = mean_biomass - lag(mean_biomass),
         interval_days = day - lag(day),
         crop_growth_rate = gain_g_m2 / interval_days)
# A tibble: 12 × 6

 3    30     3        179.       74.1            10             7.41

The crop growth rate, in g/m²/day, is the gain in biomass divided by the number of days between samplings. The first row has no previous value, so its gain is NA. arrange(day) matters: lag() uses row order, not dates, so unsorted data would give meaningless differences. Each sampling date here is a mean of independently harvested quadrats; a different set of plants is measured each time.

5.16 A summary table for an experiment report

The verbs combine into a standard descriptive table: number of observations, mean, standard deviation, standard error, and coefficient of variation for each treatment combination.

crop |>
  group_by(treatment, variety) |>
  summarise(n = sum(!is.na(yield_t_ha)),
            mean = mean(yield_t_ha, na.rm = TRUE),
            sd = sd(yield_t_ha, na.rm = TRUE),
            .groups = "drop") |>
  mutate(se = sd / sqrt(n),
         cv_percent = 100 * sd / mean) |>
  mutate(across(c(mean, sd, se, cv_percent), \(x) round(x, 2)))
# A tibble: 6 × 7
  treatment variety     n  mean    sd    se cv_percent
  <chr>     <chr>   <int> <dbl> <dbl> <dbl>      <dbl>
1 Compost   A          10  3.72  0.45  0.14      12.1 
2 Compost   B          10  3.95  0.34  0.11       8.59
3 Control   A          10  2.92  0.38  0.12      13.0 
4 Control   B          10  3.32  0.52  0.16      15.6 
5 Mineral   A          10  4.32  0.39  0.12       8.94
6 Mineral   B          10  4.39  0.3   0.1        6.88

This table describes the spread of plots within each group. It is not the CV of an experiment, which comes from the error mean square of the analysis that matches the design (see Chapter 13). Use this table to look at the data; use the design-based analysis to compare treatments.

5.18 Live R laboratory

Summarize treatment groups

Edit the code, then select Run R. The first run downloads R into your browser and may take a little time. Copy code also lets you use this example in RStudio.

trial <- data.frame(
  treatment = rep(c("Control", "Compost"), each = 4),
  yield_t_ha = c(3.1, 3.4, 3.2, 3.5, 3.9, 4.1, 3.8, 4.2)
)
aggregate(yield_t_ha ~ treatment, trial,
          function(x) c(n = length(x), mean = mean(x), sd = sd(x)))

Important formulae

Weighted mean with weights \(w_i\) (e.g. areas):

\[ \bar y_w = \frac{\sum w_i y_i}{\sum w_i} \tag{5.1}\]

Quick revision

  • filter() rows, select() columns, mutate() new variables, arrange() sort.
  • group_by() + summarise() → one row per group.
  • Join by key → never by row order; check row counts before and after.
  • Wide ↔︎ long with pivot_longer() and pivot_wider().
  • Unequal areas or sample sizes → weighted means.
