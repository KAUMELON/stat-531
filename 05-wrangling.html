5  Transforming and summarizing data with dplyr

5.1 Learning outcomes

Use selection, filtering, transformation, sorting, grouping, joins, and reshaping to answer agricultural questions while preserving observational units.

5.2 A grammar of data manipulation

select() chooses columns, filter() chooses rows, mutate() creates or changes columns, arrange() orders rows, and summarise() reduces observations to summaries. group_by() controls the groups within which later operations occur. These verbs express a sequence of data operations; the pipe passes each result to the next step.

library(dplyr)

The following objects are masked from 'package:base':

crop <- read.csv("data/crop_trial.csv")
crop |>
  filter(treatment != "Control", yield_t_ha > 4) |>
  select(plot_id, treatment, yield_t_ha) |>
  arrange(desc(yield_t_ha)) |>
  head()
  plot_id treatment yield_t_ha
1    P045   Mineral       5.16
2    P036   Mineral       4.86
3    P047   Mineral       4.84
4    P046   Mineral       4.72
5    P023   Mineral       4.55
6    P041   Compost       4.52

filter() keeps rows where its condition is TRUE; an NA condition is not retained. State explicitly whether missing records should be included. mutate() generally preserves the number of rows; summarise() changes the observational level.

crop <- crop |>
  mutate(yield_kg_ha = yield_t_ha * 1000,
         nitrogen_band = if_else(nitrogen_kg_ha >= 80, "Higher", "Lower"))
treatment_summary <- crop |>
  group_by(treatment) |>
  summarise(n_plots = n(), n_yield = sum(!is.na(yield_t_ha)),
            mean_yield = mean(yield_t_ha, na.rm = TRUE),
            sd_yield = sd(yield_t_ha, na.rm = TRUE), .groups = "drop")
treatment_summary
# A tibble: 3 x 5
  treatment n_plots n_yield mean_yield sd_yield
  <chr>       <int>   <int>      <dbl>    <dbl>
1 Compost        20      20       3.84    0.406
2 Control        20      20       3.12    0.488
3 Mineral        20      20       4.36    0.340

The treatment table has one row per treatment, whereas the original table has one row per plot. It cannot support analyses that require individual plot variation. .groups = "drop" prevents accidental retention of grouping in later operations. If every yield in a group is missing, mean(..., na.rm = TRUE) returns NaN; handle that group as having no usable estimate.

Summing monthly rainfall gives annual rainfall when all 12 months are present. Averaging monthly temperature means gives equal weight to months, not days; use day weights if the question requires a mean over days. A mean of yields is not a production-weighted regional yield unless the areas are equal.

5.4 Joining tables safely

A join links records by keys. Here the soil table has one record per plot. Verify key uniqueness and unmatched records before accepting a join. Many-to-many joins can silently multiply observations and change subsequent averages.

stopifnot(!anyDuplicated(soil$plot_id))
anti_join(crop, soil, by = "plot_id")
 [1] plot_id        block          treatment      variety        replicate     
 [6] nitrogen_kg_ha rainfall_mm    yield_t_ha     yield_kg_ha    nitrogen_band 
<0 rows> (or 0-length row.names)
linked <- left_join(crop, soil, by = "plot_id")
stopifnot(nrow(linked) == nrow(crop))
head(linked[, c("plot_id", "yield_t_ha", "ph")])
  plot_id yield_t_ha   ph
1    P001       2.42 5.48
2    P002       2.82 6.02
3    P003       2.40 6.07
4    P004       2.86 6.79
5    P005       3.52 6.44
6    P006       3.14 5.69

left_join() retains all rows of the first table, adding NA when there is no match. inner_join() retains only matched rows. A row count check is necessary but not sufficient: inspect identifier meaning and measurement timing too.

5.5 Wide and long forms

Wide tables put several measurements in separate columns; long tables use a variable column and a value column. Long form is convenient for grouped graphics.

soil_long <- soil |>
  select(plot_id, available_n_mg_kg, available_p_mg_kg) |>
  tidyr::pivot_longer(-plot_id, names_to = "nutrient", values_to = "mg_kg")
head(soil_long)
# A tibble: 6 x 3
  plot_id nutrient          mg_kg
  <chr>   <chr>             <dbl>
1 P001    available_n_mg_kg  30.2
2 P001    available_p_mg_kg  21  
3 P002    available_n_mg_kg  33.6
4 P002    available_p_mg_kg  21.8
5 P003    available_n_mg_kg  32.9
6 P003    available_p_mg_kg  16

Do not average nitrogen and phosphorus merely because both are expressed in mg/kg. They are distinct quantities. Reshaping changes representation, not scientific meaning.

5.6 Understanding what happens inside a grouped operation

When we write group_by(treatment), R does not immediately replace the observations with treatment means. It adds grouping information to the table. The next operation then acts within each group. This distinction explains why mutate() and summarise() can give very different tables after the same grouping command.

within_treatment <- crop |>
  group_by(treatment) |>
  mutate(treatment_mean = mean(yield_t_ha),
         deviation_from_treatment = yield_t_ha - treatment_mean) |>
  ungroup()
head(within_treatment[, c("plot_id", "treatment", "yield_t_ha",
                          "treatment_mean", "deviation_from_treatment")])
# A tibble: 6 x 5
  plot_id treatment yield_t_ha treatment_mean deviation_from_treatment
  <chr>   <chr>          <dbl>          <dbl>                    <dbl>
1 P001    Control         2.42           3.12                   -0.704
2 P002    Control         2.82           3.12                   -0.304
3 P003    Control         2.4            3.12                   -0.724
4 P004    Control         2.86           3.12                   -0.264
5 P005    Compost         3.52           3.84                   -0.316
6 P006    Compost         3.14           3.84                   -0.696
nrow(within_treatment)
[1] 60
nrow(treatment_summary)
[1] 3

The first result still has 60 plot rows. Every plot carries its treatment’s mean and its own deviation from that mean. The summary table has only three treatment rows. If the purpose is to investigate within-treatment variation, the first table is useful. If the purpose is a compact reporting table, the second is useful. Neither representation should be confused with additional independent replication.

The word n() counts rows in a group. It does not automatically count nonmissing yields. Thus a group can have ten rows but only eight observed yields. The quantities n(), sum(!is.na(yield_t_ha)), and mean(yield_t_ha, na.rm = TRUE) must be interpreted together.

5.7 Weighted means and unequal harvested areas

Let us suppose two farms harvest 1 ha and 9 ha, with yields of 2 and 6 t/ha respectively. Their arithmetic mean yield is 4 t/ha. However, total production is 56 tonnes on 10 ha, so the area-weighted yield is 5.6 t/ha. Both calculations are arithmetically correct; they answer different questions.

farms <- data.frame(farm = c("Small", "Large"), area_ha = c(1, 9),
                    yield_t_ha = c(2, 6))
farms <- farms |>
  mutate(production_t = area_ha * yield_t_ha)
c(mean_farm_yield = mean(farms$yield_t_ha),
  yield_from_totals = sum(farms$production_t) / sum(farms$area_ha),
  weighted_mean = weighted.mean(farms$yield_t_ha, farms$area_ha))
  mean_farm_yield yield_from_totals     weighted_mean 
              4.0               5.6               5.6

The arithmetic mean describes the average yield of these two farm records when each farm receives equal weight. The weighted mean describes production per hectare across their combined harvested area. Before reporting a district, season, or treatment summary, ask what should receive equal weight. A column of weights must have a scientific interpretation; arbitrary weights cannot improve an analysis merely by changing the result.

5.8 Joining is not matching by row position

If soil rows have been sorted by pH while crop rows remain sorted by plot number, using cbind() to combine them would attach soil measurements to the wrong plots. A join uses an identifier instead. We can demonstrate this by deliberately changing the soil row order.

soil_reordered <- soil[order(soil$ph), ]
joined_by_id <- left_join(crop, soil_reordered, by = "plot_id")
stopifnot(identical(joined_by_id$plot_id, crop$plot_id))
all.equal(joined_by_id$ph, linked$ph)
[1] TRUE

The pH values remain correctly aligned because the join uses plot_id. A correct key is therefore more valuable than a visually tidy row order. For data collected at several depths or dates, plot_id alone may not be unique; the key might need plot_id, depth_cm, and sampling_date. A one-to-many relationship can be legitimate, but the resulting observational unit must be stated.

5.9 Practical 5 and exercises

  1. Produce treatment-by-variety summaries with sample size, mean, and standard deviation.
  2. Find the five highest-yielding plots. Why is choosing their treatment after looking at the data an exploratory decision?
  3. Join crop and soil data, then summarize available nitrogen by treatment.
  4. Calculate annual rainfall only for years with 12 recorded months. Explain why sum(..., na.rm = TRUE) could understate rainfall in an incomplete year.
  5. Introduce a repeated key into a copy of the soil table and investigate its effect on the joined row count.

Chapter review. Grouping changes the level of a question. Check keys, denominators, units, and completeness whenever observations are combined.

5.10 Live R laboratory

Summarize treatment groups

Edit the code, then select Run R. The first run downloads R into your browser and may take a little time. Copy code also lets you use this example in RStudio.

trial <- data.frame(
  treatment = rep(c("Control", "Compost"), each = 4),
  yield_t_ha = c(3.1, 3.4, 3.2, 3.5, 3.9, 4.1, 3.8, 4.2)
)
aggregate(yield_t_ha ~ treatment, trial,
          function(x) c(n = length(x), mean = mean(x), sd = sd(x)))

Investigate. This base R example mirrors the grouped summaries explained with dplyr in the chapter. The simulated difference is descriptive; an experimental design is needed for causal interpretation.
