4  Cleaning agricultural observations

4.1 Learning outcomes

Identify missingness, duplicated records, inconsistent categories, and unusual observations; repair column types, labels, dates, and units; apply validation rules; distinguish a correction from an analytical choice; and document cleaning decisions in a reproducible script.

4.2 Why a cleaning log matters

A field sheet may contain a repeated entry, a missed harvest, or a measurement in the wrong unit. These are different problems. A duplicate entry may be removed after checking its identity; a missing harvest remains unknown; and a unit error requires evidence before correction. A cleaning log records the identifier, issue, action, reason, and source of verification.

The supplied crop_dirty.csv is a teaching copy with deliberate problems. It contains 61 rows for 60 unique plots, an inconsistent treatment label, two missing yields, and one suspiciously high yield. The clean file is a separate simulation, not evidence that students could ordinarily reconstruct unknown measurements.

An exact duplicate repeats every field. A repeated identifier with different measurements needs investigation, not automatic deletion. In this exercise the extra row is an exact duplicate, so removing it is defensible.

clean <- unique(dirty)
stopifnot(!anyDuplicated(clean$plot_id))
clean$treatment <- trimws(clean$treatment)
clean$treatment[clean$treatment == "control"] <- "Control"
stopifnot(all(clean$treatment %in% c("Control", "Compost", "Mineral")))

4.3 Missing data and denominators

Missingness can be informative: flood-damaged plots may be harder to harvest, and the same flooding can reduce yield. Omitting them could bias a treatment comparison. na.rm = TRUE excludes missing measurements from a calculation; it does not repair the experiment. Report how many measurements were available and investigate why values are missing.

data.frame(n_total = nrow(clean),
           n_observed = sum(!is.na(clean$yield_t_ha)),
           n_missing = sum(is.na(clean$yield_t_ha)),
           mean_observed = mean(clean$yield_t_ha, na.rm = TRUE))
  n_total n_observed n_missing mean_observed
1      60         58         2      4.386034

Do not replace all missing observations with the mean. This reduces apparent variation and understates uncertainty. Methods such as multiple imputation require explicit assumptions and are beyond this introductory course.

4.4 Flag outliers; do not delete them automatically

An outlier is unusual relative to a distribution or model. A large yield may be a data-entry error, an unusually productive plot, or evidence that groups should be analyzed separately. The interquartile range (IQR) rule flags observations outside Q1 - 1.5 IQR and Q3 + 1.5 IQR; it does not establish that they are wrong.

q <- quantile(clean$yield_t_ha, c(.25, .75), na.rm = TRUE)
spread <- diff(q)
clean$flag_yield <- !is.na(clean$yield_t_ha) &
  (clean$yield_t_ha < q[1] - 1.5 * spread |
   clean$yield_t_ha > q[2] + 1.5 * spread)
clean[clean$flag_yield, c("plot_id", "yield_t_ha")]
   plot_id yield_t_ha
10    P010       40.5

For this exercise only, the provided correction ledger represents a checked field sheet. It confirms that plot P010 was entered with a decimal error. Missing yields remain missing. In real work, keep the actual supporting document and record who checked it.

ledger <- read.csv("data/corrections.csv")
clean$yield_t_ha[match(ledger$plot_id, clean$plot_id)] <- ledger$correct_yield_t_ha
clean$flag_yield <- NULL
audit <- data.frame(
  issue = c("Exact duplicate", "Treatment spelling", "P010 decimal error", "Missing yields"),
  action = c("Removed repeated row", "Standardized to Control",
             "Used supplied verified ledger", "Retained as NA"))

4.5 Distinguishing missing, zero, and below-detection observations

Let us consider three entries in a soil analysis sheet: 0, an empty cell, and <2. These entries do not mean the same thing. Zero claims that the measured quantity is zero on the stated scale. An empty cell usually says that the measurement is unavailable. <2 says that the laboratory could not quantify the concentration below a reporting limit of 2 in the stated unit. If all three are converted to zero, information about the measurement process is lost.

Before converting a character column to numeric, inspect the distinct entries. Suppose a technician used -999 for a missing reading. That number may be numerically valid to R even though it is not a possible crop yield. The program cannot infer the field-sheet convention on its own.

recorded <- c("4.8", "", "-999", "5.2", "NA")
missing_codes <- c("", "-999", "NA")
recorded[recorded %in% missing_codes] <- NA_character_
validated_yield <- as.numeric(recorded)
validated_yield
[1] 4.8  NA  NA 5.2  NA

Here the missing-code list comes from the example’s recording protocol. Do not assume that a negative value is always missing; negative temperature or a negative change in biomass can be meaningful. A below-detection entry needs a separate indicator or a method appropriate to censored measurements. Substituting half the detection limit by habit can distort a distribution, especially when many values are below the limit.

The same principle applies to dates and units. A date such as 03/04/2024 could mean 3 April or 4 March. A number recorded in kilograms cannot be combined with tonnes merely because the column has a numeric type. Resolve these ambiguities using the source and document the resolution before fitting a model.

4.6 Checking the design while cleaning

Data quality includes the arrangement of observations. In a trial with three treatments in each of six blocks, a missing treatment-by-block combination may signal a lost plot or an import error. A missing response and a missing entire row are different: is.na() detects the former but cannot detect a plot that is absent from the table.

rcbd <- read.csv("data/rcbd.csv")
expected_design <- expand.grid(block = 1:6,
                              treatment = c("Control", "Compost", "Mineral"),
                              stringsAsFactors = FALSE)
missing_plots <- dplyr::anti_join(expected_design, rcbd,
                                  by = c("block", "treatment"))
missing_plots
[1] block     treatment
<0 rows> (or 0-length row.names)
with(rcbd, table(block, treatment))
     treatment
block Compost Control Mineral
    1       1       1       1
    2       1       1       1
    3       1       1       1
    4       1       1       1
    5       1       1       1
    6       1       1       1

The empty result from anti_join() means every expected combination is represented. It does not prove that the treatments were randomized correctly or that identifiers were transcribed correctly. Those questions require the field layout and randomization record. Cleaning and experimental design therefore meet at the point where a row is interpreted as an experimental unit.

4.7 A sensitivity analysis for a doubtful observation

Sometimes a value remains doubtful after checking the source. It may be reasonable to report analyses with and without that observation, while identifying the choice as a sensitivity analysis. The aim is to discover how strongly a conclusion depends on one record, not to select whichever analysis gives the desired answer.

trial <- read.csv("data/crop_trial.csv")
high_id <- trial$plot_id[which.max(trial$yield_t_ha)]
mean_all <- mean(trial$yield_t_ha)
mean_without_highest <- mean(trial$yield_t_ha[trial$plot_id != high_id])
data.frame(analysis = c("All observations", "Highest observation omitted"),
           n = c(nrow(trial), nrow(trial) - 1),
           mean_yield_t_ha = c(mean_all, mean_without_highest))
                     analysis  n mean_yield_t_ha
1            All observations 60        3.772000
2 Highest observation omitted 59        3.748475

This calculation does not justify removing the highest plot. It makes the effect of an exclusion visible. For treatment inference, repeat the appropriate design-based model rather than comparing overall means alone. If the conclusion changes substantially, discuss that instability and the reason for the disputed observation.

4.8 Cleaning a messy field book step by step

Real field books are typed by people working quickly, often from handwritten sheets. The simulated file field_book_messy.csv contains twelve plots from a variety trial with a net harvested area of 5 m² per plot. It has the problems you will meet most often: inconsistent labels, a comma used as a decimal mark, several codes for “not recorded”, dates in day/month/year order, a value entered in the wrong unit, and a probable decimal slip.

4.8.1 Step 1: import with the missing-value codes you know about

Start by reading the file as it is and inspecting the structure. Tell read.csv() which entries mean “missing” in this field book.

fb <- read.csv("data/field_book_messy.csv",
               na.strings = c("", "NA", "n/a", "-"))
str(fb)
'data.frame':   12 obs. of  7 variables:
 $ plot           : chr  "P01" "P02" "P03" "P04" ...
 $ sowing_date    : chr  "05/06/2025" "05/06/2025" "06/06/2025" "06/06/2025" ...
 $ variety        : chr  "V1" "v1 " "V2" "V2" ...
 $ plant_height_cm: chr  "84.5" "86.1" "79,8" "81.0" ...
 $ tillers        : int  12 14 11 NA 15 13 12 10 16 13 ...
 $ grain_wt_g_plot: num  2410 2550 2190 2275 2620 ...
 $ remarks        : chr  NA NA NA "tillers not counted" ...

str() shows the first problem. plant_height_cm was read as character, not numeric, because one entry contains a comma. Any column that should be numeric but appears as chr needs investigation before analysis. tillers and grain_wt_g_plot were read as numbers because - and n/a were declared as missing.

4.8.2 Step 2: repair types without losing information

Look at the offending entries before converting them. Converting directly with as.numeric() would silently turn "79,8" into NA.

fb$plant_height_cm[is.na(suppressWarnings(as.numeric(fb$plant_height_cm)))]
[1] "79,8" NA    
fb$plant_height_cm <- as.numeric(gsub(",", ".", fb$plant_height_cm))
summary(fb$plant_height_cm)
   Min. 1st Qu.  Median    Mean 3rd Qu.    Max.     NAs 
  78.90   80.70   85.20  154.59   91.15  850.00       1

gsub(",", ".", x) replaces every comma with a decimal point. The only remaining missing height is the lodged plot recorded as n/a, which is a genuine missing value with a reason in the remarks column. The summary also exposes a maximum height of 850 cm, which we return to in step 5.

4.8.3 Step 3: standardize category labels

table(fb$variety, useNA = "ifany")

 V3  V1 v1   V2  v3  V3 
  1   3   1   4   1   2 
fb$variety <- toupper(trimws(fb$variety))
table(fb$variety)

V1 V2 V3 
 4  4  4 
stopifnot(all(fb$variety %in% c("V1", "V2", "V3")))

trimws() removes leading and trailing spaces and toupper() converts to capitals. Before the fix, R counted six different variety labels; afterwards, three varieties with four plots each. The stopifnot() line will stop the script if a new unexpected label ever appears.

4.8.4 Step 4: convert dates explicitly

Dates typed as 05/06/2025 are ambiguous: 5 June or 6 May? The field protocol states day/month/year, so we give that format to as.Date().

fb$sowing_date <- as.Date(fb$sowing_date, format = "%d/%m/%Y")
range(fb$sowing_date)
[1] "2025-06-05" "2025-06-10"
stopifnot(!anyNA(fb$sowing_date))
harvest <- as.Date("2025-10-01")
fb$days_to_harvest <- as.numeric(harvest - fb$sowing_date)
head(fb[, c("plot", "sowing_date", "days_to_harvest")], 3)
  plot sowing_date days_to_harvest
1  P01  2025-06-05             118
2  P02  2025-06-05             118
3  P03  2025-06-06             117

In the format string, %d is day, %m is month number, and %Y is the four-digit year. If any date fails to match the format, as.Date() returns NA, which the stopifnot() check catches. Once a column has the Date class, subtraction gives the number of days between dates.

4.8.5 Step 5: check values against plausible ranges

A validation rule states the range of plausible values for each variable. The limits come from agronomic knowledge, not from the data themselves. A value outside the range is flagged for checking, not changed.

rules <- data.frame(variable = c("plant_height_cm", "tillers", "grain_wt_g_plot"),
                    min = c(30, 1, 500),
                    max = c(150, 40, 5000))
flags <- do.call(rbind, lapply(seq_len(nrow(rules)), function(i) {
  v <- rules$variable[i]
  x <- fb[[v]]
  bad <- which(!is.na(x) & (x < rules$min[i] | x > rules$max[i]))
  if (length(bad)) data.frame(plot = fb$plot[bad], variable = v, value = x[bad])
}))
flags
  plot        variable  value
1  P10 plant_height_cm 850.00
2  P07 grain_wt_g_plot   2.43

Two plots are flagged. P07 has a grain weight of 2.43, which is impossible for a 5 m² plot in grams but plausible in kilograms; the remarks column says it was weighed in kilograms. P10 has a height of 850 cm, ten times the heights of the other plots of V1, which suggests a missing decimal point.

4.8.6 Step 6: apply only documented corrections

For this exercise, assume the original field sheets were checked: P07 was confirmed as 2.43 kg, and P10 as 85.0 cm. Record the corrections in a table and apply them from that table, so the log and the data cannot drift apart.

fixes <- data.frame(
  plot = c("P07", "P10"),
  variable = c("grain_wt_g_plot", "plant_height_cm"),
  old_value = c(2.43, 850),
  new_value = c(2430, 85.0),
  reason = c("Weighed in kg; converted to g (field sheet checked)",
             "Decimal point omitted (field sheet checked)"))
for (i in seq_len(nrow(fixes))) {
  row <- fb$plot == fixes$plot[i]
  stopifnot(sum(row) == 1, fb[row, fixes$variable[i]] == fixes$old_value[i])
  fb[row, fixes$variable[i]] <- fixes$new_value[i]
}
fixes
  plot        variable old_value new_value
1  P07 grain_wt_g_plot      2.43      2430
2  P10 plant_height_cm    850.00        85
                                               reason
1 Weighed in kg; converted to g (field sheet checked)
2         Decimal point omitted (field sheet checked)

The stopifnot() inside the loop confirms that each plot exists exactly once and still holds the old value before it is changed. If someone has already corrected the file, the script stops instead of applying a correction twice.

4.8.7 Step 7: convert units and save

Grain weight in grams per 5 m² plot converts to tonnes per hectare by dividing by the plot area (g/m²), multiplying by 10,000 m²/ha, and dividing by 1,000,000 g/t.

net_plot_m2 <- 5
fb$yield_t_ha <- fb$grain_wt_g_plot / net_plot_m2 * 10000 / 1e6
round(tapply(fb$yield_t_ha, fb$variety, mean), 2)
  V1   V2   V3 
4.89 4.41 5.23 
dir.create("outputs", showWarnings = FALSE)
write.csv(fb, "outputs/field_book_clean.csv", row.names = FALSE)
write.csv(fixes, "outputs/field_book_corrections.csv", row.names = FALSE)

The raw file in data/ is never overwritten. Anyone can rerun the script from the raw file and obtain the same clean file and the same correction log.

A cleaning checklist
  1. Keep the raw file unchanged; clean with a script.
  2. Declare missing-value codes at import and check str().
  3. Inspect entries that fail numeric conversion before converting.
  4. Standardize labels and check them against the list of valid levels.
  5. Convert dates with an explicit format and confirm none became NA.
  6. Check every numeric variable against agronomically plausible ranges.
  7. Correct only with evidence, from a corrections table, and keep the log.
  8. Confirm units and convert them explicitly.
  9. Check the design: every expected plot present, no duplicates.
  10. Save the clean data and the log separately from the raw data.

Important formulae

Percentage of missing values:

\[ \%\,\text{missing} = \frac{\text{number missing}}{\text{total}} \times 100 \tag{4.1}\]

Outlier fences:

\[ Q_1 - 1.5\,\text{IQR}, \qquad Q_3 + 1.5\,\text{IQR} \tag{4.2}\]

Quick revision

  • Raw file → read only; all changes in a script.
  • Duplicate, misspelling, wrong type, impossible value → detect, document, then correct.
  • Outlier → flag and investigate; delete only with a documented reason.
  • Missing ≠ zero ≠ below detection.
  • Doubtful value → run the analysis with and without it (sensitivity).

Solutions to numerical and conceptual questions

  1. \(61 - 1 = 60\).

  4. IQR \(=1.5\); by Equation 4.2 the fences are 1.25 and 7.25; values outside are flagged.
