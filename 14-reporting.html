15  Reproducible reports with R Markdown and Quarto

15.1 Learning outcomes

Combine explanation with executable analysis, distinguish .Rmd from .qmd, add tables and figures, render HTML/PDF/Word reports, and share a project that runs in a fresh session.

15.2 A report is an argument supported by evidence

A useful report states a question, describes data and design, explains decisions, presents results, and discusses limitations. Embedding R code keeps numerical evidence connected to its computation. If a dataset changes, re-rendering updates the results. This reduces transcription errors but cannot correct an unsuitable analysis.

R Markdown usually uses .Rmd source files and rmarkdown::render(). Quarto uses .qmd source files and the quarto render command. Both can execute R through knitr. Their configuration differs: R Markdown uses output: whereas Quarto uses format:. Simply renaming an old bookdown file is not a complete migration; chapter configuration, references, chunk options, and dependencies need checking.

15.3 Anatomy of a Quarto document

The following is a complete small document. The YAML header defines metadata and formats, ordinary Markdown supplies prose, and the R chunk computes a table. Save it as report.qmd in the project folder. The separate practicals/report.qmd provides a fuller working example.

---
title: "Plant growth: a reproducible analysis"
author: "Student name"
format:
  html: default
  pdf: default
  docx: default
---

# Question

How do dry-weight measurements vary among the documented groups?

::: {#tbl-weight .cell tbl-cap='Mean dry weight by group in PlantGrowth.'}

```{.r .cell-code}
data("PlantGrowth", package = "datasets")
tab <- aggregate(weight ~ group, PlantGrowth, mean)
knitr::kable(tab, digits = 2)
```

::: {.cell-output-display}


|group | weight|
|:-----|------:|
|ctrl  |   5.03|
|trt1  |   4.66|
|trt2  |   5.53|


:::
:::

Interpret the estimates in @tbl-weight using the dataset documentation.

Use descriptive chunk labels; figure labels begin with fig- and table labels with tbl- for cross-references. A figure chunk can use #| fig-cap: "...". A hidden setup chunk may set #| include: false, but keep the source available to readers. echo: false hides code, not results. eval: false displays an example without executing it. Avoid hiding warnings until they have been investigated.

15.4 Dynamic values, figures, and interactive output

Inline R inserts a computed value into a sentence. For example, write the literal source 30 to report the number of observations. This keeps prose synchronized with the data. Do not hard-code a p-value in the discussion while the model updates elsewhere.

Use knitr::kable() for simple portable tables and ordinary R plots for graphics. HTML widgets such as Plotly need an HTML output context. In multi-format documents, test knitr::is_html_output() and use a static plot for PDF and Word, as demonstrated in the visualization chapter.

15.5 R Markdown remains part of the syllabus

The supplied practicals/report.Rmd demonstrates the same analysis in R Markdown. Its header lists html_document, pdf_document, and word_document. Run these commands in the R Console from the project root:

rmarkdown::render("practicals/report.Rmd", output_format = "html_document",
                  knit_root_dir = getwd())
rmarkdown::render("practicals/report.Rmd", output_format = "word_document",
                  knit_root_dir = getwd())
rmarkdown::render("practicals/report.Rmd", output_format = "pdf_document",
                  knit_root_dir = getwd())

15.6 Render and share

Run shell commands in the Terminal, not in the R Console:

quarto preview
quarto render --to html
quarto render --to docx
quarto render --to pdf
quarto render practicals/report.qmd --to html

PDF output requires a working LaTeX distribution, for example TinyTeX installed through quarto install tinytex. Install it only if PDF is needed. HTML is the default classroom format in the README instructions. Rendering the entire book to Word or PDF combines chapters into a single document. Opening an HTML file locally is not the same as publishing it to a public server.

Before sharing, restart R and render from source. Include source files, permitted data, metadata, package requirements, and instructions. sessionInfo() records R and loaded package versions. For a stable course release, consider a reviewed renv lockfile; do not claim that a package list alone pins an environment.

15.7 Building the report in stages

Let us develop a report in the same order as an analysis. First create the document with its question, data source, and design, even before the final model is chosen. Then add a data-check section, followed by descriptive tables and figures. Only after examining those results should the methods and model sections be completed. This sequence makes the scientific argument visible rather than hiding it behind a final table of p-values.

An effective data section identifies the observational unit, sample size, variable units, collection period, and treatment or sampling scheme. State how the raw file was obtained and whether permission is needed to share it. In the cleaning section, explain missingness, corrections, and exclusions with their consequences for the analysis. Avoid including personal or confidential identifiers merely because they happen to be in the original spreadsheet.

The methods section should name the response, predictors or factors, model, and assumptions in terms that match the actual code. If the text describes a paired test but the code fits an unpaired test, a successful render has reproduced an inconsistency. Read both parts together. The results section should lead with the size and direction of important effects, followed by uncertainty and evidence. Keep mechanistic explanations and generalization limits in the discussion.

15.8 Managing code chunks and dependencies

Each document is easiest to understand when it can be executed from top to bottom in a new session. The first chunk loads packages and reads inputs. Later chunks depend on those named objects. Avoid loading data by hand into the Environment pane and then assuming they will be available during rendering.



::: {#tbl-treatment-means .cell tbl-cap='Mean simulated grain yield by management treatment.'}

```{.r .cell-code}
means <- trial |>
  group_by(treatment) |>
  summarise(n = n(), mean_yield = mean(yield_t_ha), .groups = "drop")
knitr::kable(means, digits = 2)
```

::: {.cell-output-display}


|treatment |  n| mean_yield|
|:---------|--:|----------:|
|Compost   | 20|       3.84|
|Control   | 20|       3.12|
|Mineral   | 20|       4.36|


:::
:::

The setup chunk is hidden in the displayed report but remains in the source. It does not install packages. The table chunk visibly records the summary operation. A future reader can distinguish a count of plot records from an estimate of mean yield and can rerun both.

Caching and freezing can save time in large projects, but they can also leave stale output when dependencies are misunderstood. During textbook revision, this project uses freeze: false so examples are executed again. Do not use old cached results to claim that revised code has been checked. For serious projects, record the environment and consider a lockfile, while recognizing that external data sources can change independently of package versions.

15.9 Tables, figures, and numerical precision

A table title should say what was measured, how observations were grouped, and what the numbers represent. Put units in column headings where possible. Report enough digits for interpretation without suggesting unrealistic measurement precision. A yield measured to 0.01 t/ha should not normally be presented to eight decimal places merely because R printed them.

A figure caption should allow the graph to be understood away from the surrounding paragraph. Distinguish observed points from fitted lines, and describe error bars or shaded intervals precisely. “Error bars” is insufficient: are they SD, SE, confidence intervals, or prediction intervals? If an interactive figure permits hovering, retain axis labels and a caption so the static version remains meaningful.

Cross-references are preferable to manually typed numbers. After inserting a new table, @tbl-treatment-means updates its reference automatically. Manually writing “Table 3” can become wrong after reorganization. The same applies to chapter references and figure references. The final review should include checking that a referenced object actually supports the claim made in the sentence.

15.10 Reproducibility is also a classroom assessment

Ask a classmate to open a copy of the complete project, restart R, and render the report. If it fails, identify whether the missing component is a file, package, path, or undocumented manual step. Record the correction in the project instead of asking the classmate to imitate your Console history.

Finally, read the rendered document as a reader. Are headings in a logical order? Do tables fit? Are captions readable? Do the conclusions match the estimates? A report can be computationally reproducible and scientifically weak, or scientifically thoughtful but computationally incomplete. Undergraduate training should develop both skills together.

15.11 Getting help from an AI assistant

AI assistants can draft report templates, chunk options, and figure captions. The final chapter, Chapter 16, shows how to brief an assistant, review and verify its code, and record its contribution honestly.

15.12 Practical 16 and exercises

  1. Replace the example report’s question with a question you can answer from a documented dataset. Include source, units, design, one table, one figure, and an interpretation.
  2. Render HTML and Word. If LaTeX is available, render PDF and inspect all pages.
  3. Change one observation in a teaching copy of the data and re-render. Identify every result that should change.
  4. Explain the difference between echo: false and eval: false.
  5. Give the complete project to a classmate. Ask them to render it without relying on your Console history.

Chapter review. Reproducibility means that data, code, and computational environment support the report’s claims. A successful render is a necessary check, not a substitute for scientific review.

15.13 Live R laboratory

Generate a reproducible result sentence

Edit the code, then select Run R. The first run downloads R into your browser and may take a little time. Copy code also lets you use this example in RStudio.

yield <- c(3.2, 3.8, 4.0, 3.5, 4.6, 3.9)
result <- data.frame(n = length(yield), mean = mean(yield), SD = sd(yield))
result
cat(sprintf("Across %d simulated plots, mean yield was %.2f t/ha (SD %.2f).\n",
            result$n, result$mean, result$SD))

Investigate. Change a yield and rerun: both the table and sentence update. In a Quarto or R Markdown report, use an executable chunk for the table and inline R for values in the narrative. Rendering an entire report requires RStudio and Quarto.
